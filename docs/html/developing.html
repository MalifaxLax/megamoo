Building Your World

Shaping a place while people are standing in it.

How building here is different

In most games, the world is one thing and the program that runs it is another. You edit files, stop the game, rebuild it, start it again. Here there is nothing to rebuild: the world and everything it knows how to do are the same living thing, and you change it from inside, while it runs.

So building and programming are not separate jobs. Digging a room, describing it, and giving it some behaviour nobody expected are the same kind of act, done with the same commands, at the same time, with players walking around you.

One habit is worth forming early. Behaviour belongs to the thing that has it. A door that acts strangely gets its own instructions attached to that door — you never go and edit how doors work in general. What keeps that from becoming a mess is that objects inherit: write the common case once on something shared, then override it only where a particular object genuinely differs.

One thing to unlearn

Everyday commands are not attached to players. They live on the rooms, because the room decides what is possible in it. If you go looking for look on a character, you will not find it.
