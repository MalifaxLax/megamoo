04 · Who Can Do What

Handing out building rights without handing over the world.

On this page

The five levels

Staff powers come in five steps, each including everything below it. Giving someone gm2 makes them a builder who can dig rooms and name things, but not write code or hand out powers to anyone else.

LevelThey areAnd can
gm1Trusted playerTeleport, hold things, inspect objects.
gm2BuilderDig rooms, make exits, name and describe things, move and delete them.
gm3ProgrammerMake objects, write commands, set properties, run code.
gm4WizardRemove player accounts.
gm5OwnerGrant levels, restart and shut down the server.
> @auth Ana = add gm2 # Ana can now build > @auth Ana = remove gm2

Only gm5 may run that command — the power to hand out authority is itself the top of the ladder. Your wizard account starts there.

"Do what?" is the usual refusal

Staff commands do not announce themselves to people who may not use them. Someone without the level who tries one gets the same Do what? as if they had typed nonsense, rather than a message advertising that a powerful command exists. That is deliberate.

When you write a command of your own, say what it requires as you make it and the game will refuse it before your code runs at all:

> @adverb #3.@mycmd with auth=3 > @verbauth #3.@mycmd = 3 # or set it afterwards

Commands players should not see

Some things that look like commands are really machinery — the hooks that let one door behave oddly, for instance. Nobody should be able to type go_ and fire one directly, whatever their level.

Hiding is separate from levels: a hidden command cannot be typed by anyone, and can only be reached by other code.

> @adverb/hidden #5.at_post_move # create it hidden > @hideverb #5.at_post_move # or hide it afterwards > @unhideverb #5.at_post_move # and back again

Names ending in an underscore are hooks by convention, and names starting with one are internal. The convention is a reminder, not a rule — a hook you forget to hide is a command your players can type.

Watch for name collisions

A command attached to an object beats one inherited from further up, and this happens silently. That is the intended mechanism — it is how one object overrides shared behaviour — but it is also what actually catches people out. If a command has stopped behaving the way it does elsewhere, look for a same-named one closer to hand: +verbs <object>.
