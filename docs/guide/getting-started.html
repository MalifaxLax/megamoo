Copying and naming a world

A world is a single file. MegaMOO ships with mm.db, a starter world containing the base object library, an out-of-character lobby, a character generator, one in-character room, and a wizard account.

Do not build in mm.db. Copy it, and build in the copy — so you always have a clean starting world to go back to. Give megamoo.py two filenames: the world to copy from, and the name of the new world.

$ python3 megamoo.py mm.db mygame.db Creating new database: mygame.db Created database with 157 objects Database created successfully at mygame.db

This copies and then exits. It does not start the server — that is the next command.

Three rules for the new name

The new name must end in .db. A name ending in anything else is read as a hostname, and no copy is made. A name that is only digits is read as a port, so megamoo.py mm.db 7777 runs mm.db instead of copying it. And if a file of that name already exists it is overwritten without a prompt.

Starting a world

Use the ./mm launcher and give it the world to run:

$ ./mm mygame.db Server listening on 0.0.0.0:6770 API server listening on 127.0.0.1:7778

Two ports are reported. The first is where players connect. The second is a private door for tooling on your own machine, which is what lets an AI assistant work inside the running world.

You do not choose either number: the launcher takes the first free port from 6770 for the game and 7778 for the API, and tells you what it got. If you need a specific port — because you have told people where to connect — ask for it, and you will either get that port or a clear error:

$ ./mm mygame.db 6777

Stop a world with Ctrl-C in its terminal, or from inside the game with @shutdown.

What ./mm adds

It switches on the tooling API, supplies its password from ~/.megamoo/token, and turns on verb auto-reload so edits to command files land in the running game. For a public world with real players, run python3 megamoo.py mygame.db instead — the same server with none of those three.

Logging in

Connect with any MUD client, or with telnet:

$ telnet localhost 6770

Log in as wizard with the password megamoo. You arrive in the lobby with full authority over the world.

Change the wizard password immediately

Every copy of the starter world has the same wizard password, and it is printed in this guide. Use setpass before your world is reachable by anyone else.

Running several worlds at once

Each world is a separate process with its own file, so worlds cannot interfere with each other. Running two or three at once is normal practice: the world you care about, a scratch copy for trying things that might go badly, and perhaps last week's backup for comparison.

$ ./mm mygame.db & # game 6770, API 7778 $ ./mm scratch.db & # game 6771, API 7779 $ ./mm backup.db & # game 6772, API 7780

The same command each time, with nothing to keep track of — each world takes the next free ports and reports them. Connect to whichever you want by port: telnet localhost 6771 reaches the scratch copy.

This is what makes copying worlds useful in practice. Testing a risky change does not mean backing up and restoring. It means copying the file, running the copy alongside the original, breaking it freely, and deleting it when you are done.

Which world am I in?

With several running it is worth being deliberate. The port you connected to tells you, and so does the world's name in its own terminal. If you are working with an AI assistant, ask it to confirm which world it is pointed at before you let it change anything — "scratch" and "the real one" are one word apart.
