Hidden verbs in the MegaMOO starter

A survey of the 81 hidden verbs the starter world ships, what a reference for them would need to contain, and how much of it a generator could keep honest. Nothing here was built — this is the research that precedes writing it.

One finding corrected after the fact

The agent flagged verbs.html for listing exception verbs that "do not exist" — eat_, drink_, wear_, remove_ — and read the five called-but-undefined hooks as an invisible gap. That reading is wrong and the page needs no fixing. Exception verbs are a contract: every typeable command should have a verb_ exception after matching, so a developer can attach behaviour to an individual object. A name being called and never defined is the pattern working, not a hole in it. The rest of the report stands; this correction is Shan's.

01 Scope, measured

moo/templates/starter/world.db ships 203 verbs in 203 files, and they agree exactly — checked in both directions, no drift. Of those, 81 rows are hidden=1, carrying 107 distinct names once aliases are counted. Every one has a docstring and every one carries the Hidden:  yes line.

Aliases concentrate heavily: #1:_afflict answers to 14 names, #1:_resource and #1:_tick_up to 7 each, #1:_td_rt to 2 — four rows accounting for 30 of the 107 names.

Note rlook exists twice — #5:rlook hidden, #15:rlook not hidden but auth=3. Deliberate per its docstring, but confusing unless the reference says so.

02 What an entry must contain

A command entry is name / level / abbreviation. None of those is the right axis here — 79 of 81 have no level and none has an abbreviation. Reading the implementations, five things carry the weight.

a. How it gets called — five paths, five different absences

PathIf the verb is absentCite
call_verb(obj, 'name')raises KeyErrorbuiltins.py:1806
obj.name() method styleraises PropertyNotFound (an AttributeError) — not KeyErrorobjects.py:1019
fire_hook(...)silently returns Nonehooks.py:245
ticker callbackKeyError caught and swallowedticker.py:397
$eu effect dispatchKeyError → effect expired and dropped53/_tick.py:54

That difference bites. #17:get is written defensively — try: … except KeyError: pass at verbs/17/get.py:90 — but the same file calls pobj.do_wait() bare at line 20, a different exception on a different path. An author who removes do_wait from a custom character parent gets PropertyNotFound, not the KeyError their except is watching for.

b. What arrives in the namespace

build_verb_namespace supplies pobj/player, this, caller, location, db, verb, args, argstr, argv to everything (verb_namespace.py:534). What varies is the caller's extra kwargs, merged last and overriding (builtins.py:1850):

  • #53:do_* — tick, remaining, effect_args, effect_kwargs; all 13 handlers read remaining
  • #26:in_get, #11:on_get — dobj as a kwarg override of the parsed one
  • #23:lock_/unlock_ — iobj, the key
  • #15:gmove — dest, succ, osucc, drop, odrop, rt
  • #53:trigger/cancel/list_active — _pyargs, a sixth convention nothing else uses

c. What it must return

  • Exception hooks: return True = handled, the shared verb stops.
  • Cancellable engine hooks (before_move, before_leave, before_enter, before_recycle, before_reparent): return False cancels — and a raise is also read as False, fail-closed (builtins.py:322).
  • Value-returning helpers: #3:hands_free returns a hand label or None; #3:do_wait returns True when the character cannot act — an easy polarity trap.

d. State it writes, and the idiom

Several entries are useless without this. do_stun must reassign a whole fresh dict — an in-place mutation never reaches the database — and must use plain assignment, not setattr, because the effect runs in the character's non-wizard context. #1:_td_rt documents the same trap for rt.

03 Generated versus hand-written

More can be generated here than for commands, because the docstrings are already richer than #3's were.

Machine-readable today, no new markup

  • Object, names, aliases, hidden, auth, perms — straight from the verbs table.
  • The caller graph, with kwargs. An ast walk over all 203 verb bodies resolves callers and injected kwargs for 36 of 37 hook names. The highest-value column, and no hand table could keep up with it.
  • Engine hooks come free. moo/hooks.py already holds name, aliases, cancellable and a human description (hooks.py:326) — family 5 generates entirely from engine source, sentence included.

Needs a human sentence

  • What each hook is for — the GROUPS equivalent.
  • Return semantics: return True means "handled" for family 1 and "cannot act" for do_wait. No parser distinguishes those.
  • Three dynamic dispatch sites the AST cannot resolve — 17/get.py:60, 17/look.py:105, 53/_tick.py:44.
Do not invent new docstring fields

verb_meta.py parses exactly four, and its own docstring explains why: a Names: line that looked declarative but was prose left thirteen timers wired to nothing. A fifth field would rot the same way unless the engine parses it. If a structured Calls: line is ever wanted, derive it and have the generator write it back.

A normalisation problem first. Across the 81 docstrings, "who calls me" is spelled seven ways — Called programmatically: (18), Called: (3), Called by, Called as, Called via, Method-call interface: (4), Usage: (2). Section headers vary as widely. Any scraper needs these regularised: a one-time pass over 81 files, worth doing because the content is already there.

04 Where it should live

A new generated guide page, docs/guide/hooks.html, between verbs.html and living-world.html.

The audience is a game author extending the starter — someone who has read verbs.html, understood the exception pattern, and now needs to know which hooks exist and what arrives in them. That is reference, not tutorial, and verbs.html is already the longest page in the guide at 30KB.

Not in-game: help deliberately suppresses these and may_invoke refuses to dispatch them, so help get_ cannot work by design. Discovery tools already exist for gm3+ — +verbs/all lists hidden verbs, @vfind annotates them.

Worth a cross-link: living-world.html documents $eu.trigger(...) and do_<name> handlers without ever mentioning that tick and remaining are injected — despite all 13 shipped handlers being built around remaining.

06 Open questions

  1. Starter only, or the whole contract surface? moo/hooks.py registers 12 hook points with 20 aliases; the starter defines verbs for 4. The other 16 — at_before_move, at_object_creation, at_disconnect and the rest — are real, engine-fired, and undocumented anywhere.
  2. Six invocation conventions. Documenting all six honestly makes the page look chaotic; recommending one implies the others are deprecated, which is a design decision rather than a doc decision.
  3. Verbs that ship dead. #3:_allow has an empty body and no caller; #3:time_ok has no caller either, superseded by do_wait. Documenting dead code as an extension point is worse than omitting it.
  4. Docstring normalisation touches 81 files. Acceptable churn, and before or as part of the generator?
  5. Where does the drift check run? (Since resolved — --check is now three tests in the suite.)

07 Flagged in passing

  • Broken link in a generated page — the footer pointed at shops.html, which never existed. Fixed and republished.
  • verbs/15/help.py carries a stale comment and list. The comment describes the pre-may_invoke world. Of 35 names in _INTERNAL_EXACT, 8 do not exist in the starter (Shadowfall leftovers), 23 are already hidden=1 and dropped two lines above, and only 3 are load-bearing — mark, unmark, tt.
  • NOT_COMMANDS in the generator is dead — all three names are hidden=1, and the filter already excludes hidden verbs.
  • verbs/1/_tick_up.py still carries a prose Names: line — the exact spelling that silently broke thirteen timers. Harmless here only because a correct Aliases: line sits below it.
